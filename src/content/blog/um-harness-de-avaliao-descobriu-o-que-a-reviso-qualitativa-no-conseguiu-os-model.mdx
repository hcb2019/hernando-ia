Não fluente, não coerente, não relevante ao tópico — correto no sentido de identificar com precisão a resposta certa para o problema específico que a ferramenta foi criada para resolver. A lacuna entre "essa saída parece certa para mim" e "essa saída é verificavelmente correta" é onde a maioria das ferramentas empresariais assistidas por LLM falha silenciosamente. Elas passam pela revisão interna porque a saída parece correta. Elas falham em produção porque essas pessoas não estavam revisando com base na verdade fundamental — estavam revisando com base na intuição sobre como uma boa resposta deveria ser. Essa distinção importa cada vez mais à medida que as ferramentas assistidas por LLM deixam de ser acessórios de produtividade para se tornarem componentes que influenciam decisões de negócios reais. Se a sua ferramenta assistida por IA está moldando como um analista investiga um problema de qualidade de dados, como um revisor de conformidade decide se deve escalar um registro sinalizado, ou como uma equipe de operações prioriza uma falha de validação — a precisão da sua saída tem consequências reais. "Parece razoável" não é um padrão de avaliação adequado para isso. O que a avaliação qualitativa realmente captura: A abordagem padrão de avaliação para saídas de LLM em ferramentas empresariais é qualitativa: uma amostra das saídas é revisada por alguém com conhecimento de domínio, julgada contra um modelo mental do que uma boa resposta deveria ser, e o prompt é ajustado se muitas saídas parecerem erradas. Isso captura uma classe específica de problemas: saídas que são obviamente erradas, mal formatadas ou fora do tópico. Esses são problemas reais que valem a pena capturar. Eles também são os fáceis.
